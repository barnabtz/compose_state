📋Project Overview

Compose State is a comprehensive Flutter state management package inspired by Jetpack Compose, offering reactive state, centralized ViewModel scoping, API handling, and persistence for basic, complex, and dynamic objects.

🌟 Key Features

🔄 Reactive State Types

MutableState, PersistableState, ApiState, DerivedState, HistoryState, StreamState, and SignalState for every use case.

🛡️ Error Handling

Comprehensive error recovery strategies, retry mechanisms, and error boundaries with automatic fallbacks.

🧠 Memory Management

Automatic disposal, weak reference tracking, and memory leak detection for optimal performance.

⚡ Performance Optimization

Deep equality checking, notification batching, and optimized rebuilds for smooth user experiences.

🧪 Testing Infrastructure

Mock implementations, state change tracking, and comprehensive testing utilities.

🔒 Type Safety

Runtime type validation for serialization and persistence operations with compile-time safety.

✨Best Practices & Performance

🎯 Correct Factory Functions

  • mutableStateOf(value) - Basic reactive state
  • persistableState(value, fieldName: 'key', persistable: this) - Persistent state
  • apiStateOf(errorHandler: handler) - API state
  • derivedStateOf(computation, dependencies: [...]) - Computed state
  • streamStateOf(stream, initialValue) - Stream-based state
  • historyStateOf(value) - State with undo/redo

⚡ Performance Optimization

  • Use OptimizedStateBuilder for expensive widgets
  • Always specify dependencies in derivedStateOf
  • Batch state updates when possible
  • Dispose states properly in ViewModels
  • Use ViewModelScope for proper lifecycle management

🛡️ Error Handling

  • Always provide StateErrorHandler for API states
  • Implement retry strategies for network calls
  • Use UiState pattern (Loading, Success, Error)
  • Handle edge cases in state builders

🧪 Testing Strategy

  • Use mockStateOf() for testing
  • Test ViewModels separately from UI
  • Use StateTestUtils for state change tracking
  • Test error scenarios and edge cases

🏗️ Architecture Guidelines

  • Use ComposeViewModel with Persistable mixin
  • Wrap apps with ViewModelScope
  • Separate business logic from UI components
  • Follow clean architecture principles

🔒 Common Mistakes to Avoid

  • ❌ Using persistableStateOf() (doesn't exist)
  • ❌ Missing dependencies in derivedStateOf()
  • ❌ Not using ViewModelScope for persistence
  • ❌ Forgetting to call fetch() on ApiState
  • ✅ Use the correct APIs shown in examples
